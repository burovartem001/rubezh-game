# Рубеж

Браузерная мобильная стратегия: тыловой полигон взвода БПЛА, подготовка операторов, транспорт, оснащение, командир
и асинхронные походы на карту из 12 секторов. Игровой мир, карта, стороны и характеристики техники вымышлены и условны.

- **Клиент:** React + TypeScript (Vite), адаптивный интерфейс с приоритетом смартфона, устанавливается на главный экран.
- **Сервер:** Node.js + TypeScript (Express). Считает ресурсы, таймеры, право на действия, бой и награды.
- **Хранилище:** PostgreSQL, миграции в `server/migrations`.
- **Размещение:** один сервис на Railway + база Postgres на Railway.

## Как устроено

```
shared/config.ts     баланс: цены, длительности, характеристики, секторы, награды, обучение (единый источник)
shared/calc.ts       расчёт похода: стоимость, длительность, прогноз и итог боя (детерминированный)
server/src/          API: вход (auth.ts), состояние и «досчёт» времени (game/state.ts), действия (game/actions.ts)
server/migrations/   SQL-миграции, применяются автоматически при запуске
client/src/          экраны: Полигон, Карта, Отряд, Командир, Отчёты
tests/               тесты расчёта (calc) и сценарий через API (api)
```

**Время.** Сервер хранит абсолютные отметки начала и завершения (строительство, обучение, мастерская,
восстановление, походы). Фоновых процессов нет: при каждом запросе состояние игрока «досчитывается» до текущего
момента в хронологическом порядке — производство ресурсов (с остановкой на вместимости хранилищ), завершение очередей
и походов. Поэтому всё корректно завершается после отсутствия игрока и после перезапуска сервера.

**Надёжность.** Каждое действие выполняется в транзакции под замком строки игрока (`SELECT … FOR UPDATE`) —
одновременные запросы одного игрока выполняются по очереди. Клиент передаёт `requestId`; повтор с тем же
идентификатором (обрыв связи, двойное нажатие) возвращает прежний ответ без повторного списания. Итог похода
рассчитывается в момент отправки с зафиксированным случайным фактором и раскрывается по завершении; выдача
награды защищена переводом статуса `active → done` и уникальным отчётом на поход (`reports.expedition_id UNIQUE`).
Ограничения `CHECK (… >= 0)` в базе не дают уйти ресурсам и счётчикам операторов в минус.

**Цикл похода:** выбор сектора → задание → состав (операторы, один транспорт, до двух предметов оснащения) →
прогноз-диапазон и цена → отправка (ресурсы списаны, участники зарезервированы) → этапы «в пути / задание /
возвращение» → отчёт: итог, награды, опыт, потери, повреждения, изменение разведки и контроля, причины результата.

### Игровые допущения

- Операторы хранятся количествами по типам; у каждого типа есть ранг 1–5 (улучшение в центре подготовки).
- Потери делятся на раненых (возвращаются после платного восстановления), восстановленных в поле (ремкомплект)
  и безвозвратные. Безвозвратных потерь нет на секторах сложности 1–2, там же потери ограничены половиной группы.
- Разведанность сектора даёт до +15% к силе и сужает прогноз; опорный пункт доступен с разведанностью 50%.
- Транспорт: мотоцикл (быстрее), электровелосипед (экономнее, бонус к разведке), «Буханка» (вместительнее, больше
  добычи). Пикап показан как следующий этап. Повреждённый транспорт ремонтируется в мастерской.
- Командир: 10 уровней, одно очко навыка за уровень, три ветки по три навыка, один бесплатный сброс
  (дальше — за данные). Второй слот похода — командный пункт 4 ур., третий — навык «Второй эшелон».
- Ежедневные задания необязательны и не блокируют прогресс. Доната, ускорений и рекламы нет.
- Все числа баланса — в `shared/config.ts`; интерфейс берёт подписи и цены оттуда же.

## Локальный запуск

Нужны Node.js 20+ и PostgreSQL 14+.

```powershell
npm install
copy .env.example .env      # укажите DATABASE_URL
npm run build
$env:DATABASE_URL="postgres://rubezh:rubezh@localhost:5432/rubezh"; npm start
```

Откройте http://localhost:3000. Миграции применяются при запуске (отдельно — `npm run migrate`).

Режим разработки с горячей перезагрузкой: `npm run dev` (сервер на :3000, клиент на :5173 с прокси `/api`).

PostgreSQL в Docker: `docker run -d --name rubezh-pg -e POSTGRES_USER=rubezh -e POSTGRES_PASSWORD=rubezh -e POSTGRES_DB=rubezh -p 5432:5432 postgres:16`

### Проверка

```powershell
npm test                                   # расчёт боя, влияние оснащения/транспорта/навыков, защита начального этапа
$env:TEST_URL="http://localhost:3000"; npm run test:api   # полный первый цикл через API (нужен DATABASE_URL той же базы)
npm run test:awards; npm run test:chevrons; npm run test:long   # награды, шевроны, системы долгой игры (нужен INTEGRATION_KEY)
npm run test:depth                         # конструктор, износ, бойцы, передовые пункты, кампания, события, достижения, встречи
```

## Railway

Проект — отдельный проект Railway из двух сервисов: **Postgres** и **rubezh** (этот репозиторий).

1. New Project → Deploy PostgreSQL.
2. В том же проекте: New → GitHub Repo → этот репозиторий. Сборка и запуск описаны в `railway.json`
   (`npm install --include=dev --no-audit --no-fund && npm run build`, старт `npm start`, проверка `/api/health`).
3. Переменные сервиса rubezh:
   - `DATABASE_URL` = `${{Postgres.DATABASE_URL}}` (ссылка на внутренний адрес базы);
   - при необходимости `FRAME_ANCESTORS`, `BASE_PATH` (см. ниже).
4. Settings → Networking → Generate Domain.

Миграции выполняются при каждом запуске сервиса (под advisory-замком, повторно не применяются).
Секретов в репозитории нет; пароли хранятся хешами scrypt, токены сессий — хешами SHA-256.

## Награды за заслуги (сайт «Учёт дронов»)

Особые бойцы, транспорт и оснащение чуть сильнее стандартных. Их нельзя обучить, построить, купить или разобрать —
они выдаются только сайтом «Учёт дронов». Условия выдачи задаются на стороне сайта.

| Ключ | Награда | Что даёт |
|---|---|---|
| `veteran` | Бывший штурмовик | сила 7 (FPV — 6), сам реже попадает в потери, −4% потерь группы за бойца (до −16%) |
| `gyro` | Гироскутер | время −10%, топливо −60%, разведка +14% (лучше электровелосипеда) |
| `niva` | Золотая Нива | группа +3, добыча +15%, без замедления, топливо +30% (лучше «Буханки») |
| `rebNew` | РЭБ нового образца | потери −18% (улучшенный РЭБ — −15%) |
| `nsuRubicon` | НСУ, брошенное Рубиконом | FPV +21% (улучшенная НСУ — +18%) |
| `pigGear` | Снятое со свиньи снаряжение | потери −12% и сила группы +4% |
| `fpvBoevye` | FPV-дрон, купленный на боевые | сила всей группы +8% |
| `mavicField` | Дрон Mavic, найденный в поле | разведка и данные +18% (улучшенный комплект связи — +15%) |

Повторно выданный транспорт повышает свой уровень. В группу нельзя взять два предмета с одинаковым эффектом.

**API выдачи.** Включается переменной `INTEGRATION_KEY` (случайная строка от 16 символов; тот же ключ хранится на сайте).

```
GET  /api/integration/awards                       каталог наград
POST /api/integration/award                        выдать награду
Authorization: Bearer <INTEGRATION_KEY>
{ "login": "логин игрока в Рубеже", "award": "niva", "count": 1, "reason": "Лучший учёт месяца", "externalId": "event-123" }
```

`externalId` — идентификатор события на сайте: повтор запроса с тем же значением не выдаст награду второй раз.
Игрок увидит награду при следующем входе (праздничная вспышка, уведомление, история у командира).

## Долгая игра

Код систем — `shared/progression.ts` (числа и правила), `server/src/game/meta.ts` и `server/src/game/social.ts`.

- **Удержание секторов.** Контроль держится сутки после успешного рейда или штурма, потом падает на 2% в час.
- **Атаки на полигон.** Примерно раз в 8 часов противник может напасть (после обучения, со 2 уровня). Оборона = здание
  «Оборона полигона» + свободные операторы дома. Проигрыш — часть запасов сверх 40% вместимости, раненые и потеря контроля сектора.
- **Исследования** за данные: 4 ветки по 4 ступени (связь, БПЛА и оборона, логистика, медицина), одно за раз, ступени открывает узел связи.
- **Именные бойцы.** У каждого оператора позывной, черта характера, опыт (уровни 1–5), шрамы. В поход идут самые опытные; гибель — в «Помним».
- **Обстановка на карте** (общая для всех): погода каждые 6 часов и «горячая цель» каждые 3 часа (награды ×2).
- **Экспедиции** — многочасовые походы (со 2 уровня, разведка сектора от 30%), награда примерно в 8 раз больше рейда.
- **Сезоны** по 4 недели: тема с модификаторами и сюжет из пяти задач. **Рейтинг** недели и сезона с наградами топ-1/3/10.
- **Недельные контракты** (3 на неделю, по уровню) и **серия ежедневных входов** (7-дневный цикл).
- **Роты** до 20 командиров: склад, выдача со склада, помощь в стройке (−6% времени, до 5 раз), еженедельный штурм укрепрайона.
- **Набеги** на полигоны других командиров (с 3 уровня, ±2 уровня). Защита: новички (до 3 уровня или 72 часа), 8 часов щита после набега,
  повтор по той же цели — через 12 часов, своих по роте трогать нельзя. Последствия применяются обороняющемуся при его входе.
- **Комплекты нашивок** дают постоянные бонусы. **Престиж** на 10 уровне: полигон начинается заново с постоянным бонусом (до 5 раз).
- **Привязка к «Учёту дронов»:** игрок получает код в «Командир → Профиль», сайт вызывает `POST /api/integration/link`
  `{ code, siteUserId }`; после этого награды можно выдавать по `siteUserId` вместо `login`.

## Глубина полигона и сюжет

Данные и чистые функции — `shared/content.ts`, общий для сервера и интерфейса расчёт бонусов и цен — `shared/deepcalc.ts`,
серверная логика — `server/src/game/deep.ts`, интерфейс — `client/src/screens/Deep.tsx`, таблицы — миграция `005_depth.sql`.

- **Новые здания** (строятся с нуля): автопарк (дешевле улучшать технику, с 3 ур. — пикап), ремонтная зона (дешевле ремонт, медленнее износ),
  медпункт (быстрее восстановление, сведение шрамов), аналитический центр (точнее прогноз, больше данных, расшифровка чертежей),
  полигон испытаний (конструктор дронов, усиливает модели).
- **Конструктор дронов:** модель на класс операторов из 6 деталей (рама, моторы, аккумулятор, камера, нагрузка, связь); 7 деталей — по чертежам.
  Эффект модели пропорционален доле её класса в группе. Чертежи — из кампании, опорных пунктов, событий, встреч и аналитического центра.
- **Износ:** оснащение −5% и модели −4% прочности за поход; ниже 50% эффект слабеет, на нуле предмет не берут в поход. Ремонт — за комплектующие.
- **Бойцы:** специализация с 3 уровня (по 2 на класс), инструкторы с 5 уровня (до 2, подготовка быстрее), усталость после походов
  (снимается за часы), расчёты — пары, прошедшие вместе 10 походов, дают бонус группе.
- **Передовые пункты** (КП 6 — один, КП 8 — два): ставятся в секторе с контролем от 50%, сокращают путь и расход топлива в этот и соседние секторы;
  противник атакует их по тем же правилам, что и полигон.
- **Кампания:** 5 глав, 21 шаг — сцены с героями, задания с ограничениями (состав, ночь, модель дрона), цели и выборы.
  Выбор меняет реплики и награду, но не закрывает путь.
- **События выходных** (пятница 18:00 — понедельник 06:00 МСК, по кругу): ночная охота, конвой, буря, неделя мастерской, оборона рубежа.
  Очки за действия, 4 ступени наград (на третьей — чертёж, на четвёртой — шеврон события). Награды прошлого события можно забрать до следующего.
- **Достижения:** 22 линии по 3 ступени, очки и звание (видно в профиле у сослуживцев).
- **Случайные встречи** в 18% походов: решение в отчёте, иногда — талисман (кот Пулемёт, пёс Сапёр) с постоянным бонусом.

## Шевроны

Отличительные знаки командира. Один шеврон «носится на рукаве» и виден другим игрокам в профиле вместе со всей коллекцией
(вкладка «Командир → Сослуживцы»). Каталог и условия — `shared/chevrons.ts`.

- **Стартовые** — выдаются всем.
- **За достижения в игре** — открываются автоматически (первый вылет, 10 рейдов, взятый опорный пункт, 5 уровень командира и т. д.).
- **Возможно получить за особые заслуги на сайте** — выдаёт сайт «Учёт дронов» через тот же API наград:
  `siteAccountant`, `siteProp`, `siteHands`, `siteNight`, `siteSupport`, `siteVeteran` (поле `award`).

Редкость: «Обычный», «Редкий», «Эпический», «Легендарный». Уставные пока все «Обычный»; меняется в `shared/chevrons.ts`.

## Встраивание в основной сайт

Игра — самостоятельное приложение, но готова к подключению к основному сайту двумя способами:

- **Фрейм.** На странице сайта: `<iframe src="https://<адрес-игры>/" style="width:100%;height:100vh;border:0" allow="fullscreen"></iframe>`.
  В переменной `FRAME_ANCESTORS` игры укажите адрес сайта, например `'self' https://104-171-130-39.sslip.io`.
  Вход работает через токен в заголовке `Authorization`, поэтому не зависит от сторонних cookie в Safari.
- **Под путём сайта** (например `/game`) через обратный прокси (Caddy: `handle_path /game/* { reverse_proxy <адрес-игры> }`).
  Клиент собран с относительными путями (`base: './'`) и обращается к API относительно страницы, так что работает под
  любым префиксом. Если прокси не срезает префикс — задайте игре `BASE_PATH=/game`.

Общий вход с учётными записями основного сайта — отдельная задача: точка подключения — `server/src/auth.ts`
(выдача токена сессии по проверенному пользователю сайта).
